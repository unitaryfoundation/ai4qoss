# Bug report

Last verified: 2026-07-29
Status: draft

## Task

File a bug report that a maintainer can act on. Done means: a minimal reproducing test
or script, the observed and expected behavior, and the environment pin.

## Loop

1. Agent (or human with an assistant) reduces the failing case to a minimal script or
   test.
2. Runs it in a clean pinned environment against the latest development head to confirm
   it fails, and against the latest release to check whether it is already fixed.
3. Files the report with the reproduction attached and the disclosure footer.

## Check

The reproduction itself: it must fail on the current head, in a clean environment,
deterministically (fixed seed for probabilistic behavior, with the tolerance stated).

- Cost: one clean-environment run.
- Where it can be fooled: environment-dependent failures that vanish in the
  maintainer's setup. The pin plus a container reference limits this.

## Guardrails

- Rule for the receiving repo: reports without a reproduction are not reviewed. State
  this in CONTRIBUTING and close non-conforming reports with a pointer to it.
- Reports generated by scanning tools without a run-confirmed reproduction are not
  accepted.
